# 우리 반 하루 체크

초등학교 5학년 27명 학급용 정적 체크리스트입니다. 빌드나 별도 설치 없이 GitHub Pages에서 배포할 수 있습니다. 한국어 UI이며 PC·태블릿에 대응합니다.

## 구성
- `index.html`: 화면과 접근성 레이블, 설정/연결 모달입니다.
- `style.css`: 반응형 스타일과 축하 효과입니다.
- `app.js`: 날짜별 기록, 통계, 로컬 저장, JSONbin 동기화입니다.
- `.nojekyll`: GitHub Pages에서 정적 파일로 제공합니다.
- `TEST-CHECKLIST.md`: 배포 전 수동 검증 절차입니다.

## 배포
1. GitHub 저장소를 만들고 압축 파일을 해제한 폴더 안의 파일들을 저장소 루트에 올립니다. `index.html`이 루트에 있어야 합니다.
2. 저장소의 Settings → Pages에서 Deploy from a branch를 선택하고 main 브랜치의 /(root)를 지정하여 저장합니다. 메뉴 이름은 GitHub UI에 따라 달라질 수 있습니다.
3. 배포된 HTTPS 주소를 PC와 태블릿에서 엽니다. API 키와 학생 데이터는 GitHub에 올리지 않습니다.
4. 로컬 확인은 HTTP 서버를 권장합니다. Python 설치 환경에서는 해당 폴더에서 `python -m http.server 8000`을 실행하고 `http://localhost:8000`에 접속합니다.

## JSONbin 연결
1. https://jsonbin.io 에서 계정을 준비합니다. 이 앱 전용 비공개 Bin을 생성하고 초기 내용은 `{}`로 지정합니다.
2. Bins Read와 Bins Update에 필요한 권한을 가진 Access Key를 발급합니다. 가능한 한 좁은 권한을 사용하고, 서비스에서 지원하는 범위 제한을 확인합니다. Master Key는 사용하지 않습니다.
3. 앱의 클라우드 연결에서 Bin ID와 Access Key를 입력합니다. 모든 기기에서 같은 Bin을 사용합니다.
4. 기본 조회 간격은 15초이며 5/30/60초로 바꿀 수 있습니다. 확인 주기를 줄이면 API 요청량이 늘어납니다. 계정의 요금제·요청 한도를 확인하세요.
5. 연결 전 로컬 모드에서 작성한 기록을 옮기려면 '아직 연결하지 않은 로컬 기록도 이 Bin에 병합'을 선택합니다. 기본값은 선택 안 함이며, 다른 학급 기록이 섞이지 않도록 Bin별 브라우저 저장소를 구분합니다.
6. 키는 기본적으로 메모리에만 존재합니다. '이 탭을 닫을 때까지 키 보관' 선택 시 sessionStorage에 저장됩니다. 브라우저 세션 복원 기능은 이를 복원할 수 있으므로 공유 기기에서는 반드시 연결 해제를 누르세요. 이름·메모·체크는 localStorage에 남습니다.
7. 새로고침 시 키를 기억하지 않았다면 로컬 모드가 먼저 보입니다. 동일 Bin으로 재연결하면 그 Bin의 캐시와 클라우드 기록을 다시 불러옵니다.

## 사용 방법
- 학급 설정에서 27명의 번호·이름을 바꿀 수 있습니다. 번호는 1~999의 서로 다른 정수입니다.
- 우유 대상은 콤마로 구분합니다. 기본 대상은 0명이며, 지정한 학생에게만 우유 체크박스가 활성화됩니다. 번호를 수정했다면 우유 입력란에도 수정 후 번호를 입력하세요.
- 날짜 선택기는 해당 날짜의 체크와 메모를 보여줍니다. 명렬과 우유 대상, 추가 항목 설정은 전체 날짜에 공통이며, 과거 날짜의 통계도 현재 설정으로 계산됩니다. 날짜별 대상자 이력 스냅샷 기능은 없습니다.
- 비고는 학생별·날짜별 최대 500자입니다. 학생 이름은 최대 40자, 추가 항목 이름은 최대 30자입니다.
- 추가 항목은 네 번째 열 한 개입니다. 이름을 바꾸어도 동일한 열의 과거 기록이 유지됩니다. 사용 해제 후 다시 켜면 기록이 복원됩니다.
- 전체 달성률은 '완료 체크 수 / 활성 항목의 대상 체크 수'입니다. 우유 비대상자와 비활성 추가 열은 분모에서 제외합니다. 추가 열이 켜져 있으면 포함합니다.
- 미완료는 해당 학생에게 적용되는 활성 항목 중 하나라도 미완료인 상태입니다. 메모 유무는 완료 판단에 영향을 주지 않습니다.
- 열 제목은 필터 결과뿐 아니라 전체 대상자를 일괄 체크·해제합니다. 항목 또는 학급 전체 완료 시 축하 효과가 나타납니다. 동작 줄이기 설정에서는 애니메이션 없이 완료 문구를 표시합니다.
- 백업 다운로드는 키를 제외한 전체 데이터와 동기화 대기 상태를 JSON 파일로 내보냅니다. 복원 UI는 이 버전에 없습니다. 복구하려면 별도 보관한 백업의 `doc` 객체를 새 Bin의 내용으로 넣고 그 새 Bin으로 연결하세요. 기존 Bin과 다른 새 Bin을 사용해야 기존 로컬 캐시가 복원 값을 재병합하는 것을 피할 수 있습니다.

## 동기화 방식과 한계
- UI는 네트워크 응답을 기다리지 않고 기본 27명과 로컬 캐시로 렌더링합니다.
- 수정은 즉시 localStorage에 저장하고, 마지막 수정 후 750ms에 동기화를 시도합니다.
- `GET /v3/b/{BIN_ID}/latest?meta=false`로 원격 내용을 읽고 필드별 병합 후 필요할 때 `PUT /v3/b/{BIN_ID}`로 전체 문서를 저장합니다. PUT 후 다시 GET하여 확인합니다.
- 각 필드에는 값(v), 수정 시각(t), 클라이언트 식별자(c)를 저장합니다. 학생 내부 ID(s01~s27)는 번호·이름과 무관하게 고정입니다. false와 빈 메모도 명시적인 수정값으로 남습니다.
- 서로 다른 학생/항목의 변경은 필드별 최신 수정값으로 병합합니다. 같은 필드 충돌은 수정 시각이 큰 값, 동률이면 클라이언트 식별자 순으로 선택합니다. 관측한 원격 시각보다 새 수정 시각이 커지도록 처리하지만 기기 시계 차이는 의미적인 최신 순서를 왜곡할 수 있습니다. 모든 기기의 자동 시각 설정을 권장합니다.
- **JSONbin 전체 PUT에는 이 구현에서 사용하는 원자적 비교·교환 또는 서버 트랜잭션이 없습니다. 따라서 동시 편집 무손실, 강한 일관성, 확정적인 실시간 동기화를 보장하지 않습니다.** 읽기-수정-쓰기 사이의 경쟁으로 이미 저장된 변경도 일시적으로 덮어써질 수 있습니다. 다음 조회에서 각 기기의 로컬 복사본을 병합하여 대부분 회복하지만, 해당 복사본까지 사라지면 복구할 수 없습니다. 중요한 운영에서는 한 기기씩 편집하고 정기 백업을 권장합니다.
- 같은 기기의 여러 탭도 storage 이벤트로 변경을 병합하지만 localStorage 역시 트랜잭션 저장소가 아닙니다. 한 기기에서는 한 탭 사용을 권장합니다.
- 설정 모달은 사용자가 바꾼 필드만 저장하여 다른 날짜/학생 기록을 초기화하지 않습니다. 학생 번호 중복을 저장 전 검사하지만 다른 기기의 동시 번호 변경은 중복을 만들 수 있습니다. 명렬 설정은 한 기기에서만 수정하세요.
- 네트워크 요청은 10초에 취소합니다. 실패 시 최대 5분까지 재시도 간격을 늘립니다. 요청 제한(429)도 지수 백오프합니다. 인증/권한 실패 및 잘못된 Bin 데이터는 자동 재시도를 멈추고 재연결을 요구합니다.
- 비활성 탭은 주기 조회를 쉬고 다시 활성화할 때 확인합니다. 기기 절전·브라우저 백그라운드 제한·네트워크 상태에 따라 표시 간격보다 늦어질 수 있습니다.
- 서비스 워커는 포함하지 않습니다. **이미 열린 화면에서는 오프라인 편집이 가능하지만, 완전 오프라인 상태에서 새로 여는 기능은 보장하지 않습니다.**
- 모든 날짜를 하나의 Bin에 저장합니다. 이력 증가 시 계정의 문서 크기 한도 및 GET/PUT 전송 비용을 확인하고 학기 단위로 백업/새 Bin을 운영하세요.
- `X-Bin-Versioning: false`를 사용하므로 JSONbin 버전 기록에 복구를 의존하지 말고 별도 백업을 보관하세요.

## 보안과 학생 개인정보
- GitHub Pages는 공개 정적 호스팅입니다. 이 앱에는 로그인, 교사 권한 검증, 서버 측 비밀 키 보관이 없습니다. Access Key를 아는 사용자는 허용된 범위에서 데이터에 접근할 수 있습니다.
- 브라우저에서 JSONbin에 직접 연결하므로 키를 사용 기기 사용자·개발자 도구·악성 확장 프로그램으로부터 숨길 수 없습니다. 전용 비공개 Bin과 최소 권한 Access Key를 사용하세요. 공개 저장소에 키를 넣지 마세요.
- 학생 이름과 비고는 개인정보일 수 있습니다. 학교 승인, 처리방침, 접근 권한, 보관 기간, 국외 이전·외부 클라우드 사용 관련 요건을 검토하세요. 초기 테스트는 기본 가명으로 하고 건강 정보·연락처 등 민감한 정보는 기록하지 않는 것을 권장합니다.
- 공유 PC에서는 로컬 캐시와 다운로드한 백업도 개인정보입니다. 연결 해제는 키만 제거하며 데이터 캐시를 삭제하지 않습니다. 브라우저 사이트 데이터 정리 시 미동기화 데이터가 유실될 수 있으므로 백업 및 클라우드 반영 여부부터 확인하세요.
- 엄격한 보안과 동시성 보장이 필요하면 인증을 제공하는 서버/프록시와 트랜잭션 데이터베이스를 사용해야 합니다. 이 버전의 JSONbin 직접 연결만으로는 충족되지 않습니다.
- 외부 JS 라이브러리와 CDN 없이 실행하며, 화면 문자열은 textContent/value로 표시합니다. CSP로 스크립트와 API 연결 출처를 제한합니다.
